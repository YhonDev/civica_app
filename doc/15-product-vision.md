# VigiVecino
## Product Vision

Version: 1.0
Platform: Flutter (Android / iOS)
Backend: NestJS
Architecture: Clean Architecture
Design Target: Premium Mobile Experience (2026)

---

# 1. Visión

VigiVecino no es una aplicación para registrar pagos.

Es una plataforma inteligente para la gestión del recaudo de comunidades residenciales.

Su objetivo principal es facilitar la interacción entre propietarios, cobradores y administradores mediante una experiencia moderna, intuitiva y extremadamente simple.

La aplicación prioriza la rapidez, la claridad y la confianza sobre la cantidad de funcionalidades visibles.

Cada pantalla debe mostrar únicamente la información necesaria para la tarea que el usuario necesita realizar en ese momento.

---

# 2. Objetivos del Producto

El producto debe permitir:

- Centralizar la administración del conjunto.
- Administrar propietarios, viviendas y estructuras del conjunto.
- Gestionar el ciclo completo del recaudo.
- Facilitar el trabajo diario de los cobradores.
- Permitir que el propietario consulte su estado financiero.
- Generar información útil para la administración.
- Mantener una trazabilidad completa de todas las operaciones.

---

# 3. Filosofía

La aplicación nunca debe sentirse como un ERP.

Nunca debe sentirse como un sistema administrativo tradicional.

Debe sentirse como una aplicación móvil moderna.

Las acciones importantes siempre estarán a uno o dos toques.

Las tareas repetitivas deben requerir el menor número posible de interacciones.

El usuario nunca debe navegar entre muchas pantallas para completar una tarea sencilla.

---

# 4. Principios

Toda decisión de diseño debe cumplir estos principios.

## Simplicidad

Mostrar solamente la información necesaria.

Eliminar cualquier elemento que no aporte valor.

---

## Rapidez

Cada acción frecuente debe realizarse en menos de 15 segundos.

Registrar un pago debe ser un proceso extremadamente rápido.

---

## Claridad

Cada pantalla responde únicamente una pregunta.

Ejemplo:

Propietario

¿Cómo está mi cuenta?

Cobrador

¿Qué debo hacer hoy?

Administrador

¿Cómo está el recaudo del conjunto?

---

## Consistencia

Todos los roles comparten el mismo lenguaje visual.

- mismas tarjetas
- mismos botones
- mismos colores
- mismas animaciones
- misma navegación

Solo cambia la información mostrada.

---

## Escalabilidad

La aplicación debe poder crecer sin rediseñar la experiencia.

Las futuras funcionalidades como:

- Nequi
- BRE-B
- PSE
- WhatsApp
- IA
- Reportes avanzados

deben integrarse sin modificar la estructura principal de la aplicación.

---

# 5. Público objetivo

La aplicación está diseñada para tres tipos de usuarios.

## Administrador

Responsable de la administración general del conjunto.

Toma decisiones.

Administra.

Supervisa.

Audita.

Configura.

---

## Cobrador / Vigilante

Usuario operativo.

Trabaja en campo.

Registra pagos.

Consulta propietarios.

Actualiza información.

No administra el sistema.

---

## Propietario

Consulta su información.

Consulta pagos.

Consulta cartera.

Solicita revisión cuando detecta inconsistencias.

Nunca modifica información financiera.

---

# 6. Qué NO es la aplicación

La aplicación NO es:

- un sistema contable
- un ERP
- una hoja de Excel móvil
- un CRUD tradicional
- un sistema lleno de formularios

---

# 7. Qué SÍ debe sentirse

Al utilizar la aplicación el usuario debe sentir:

- rapidez
- confianza
- simplicidad
- orden
- modernidad
- fluidez

La interfaz debe parecer un producto premium.

Nunca un software empresarial antiguo.

---

# 8. Inspiración

La experiencia de usuario toma inspiración de productos como:

- Linear
- Revolut
- Apple Wallet
- Arc Browser
- Notion
- Airbnb
- Stripe Dashboard
- Vercel Dashboard

No se busca copiar su apariencia.

Se busca adoptar su filosofía de simplicidad, claridad y velocidad.

---

# 9. Regla más importante

La aplicación siempre debe responder una sola pregunta por pantalla.

Si una pantalla intenta responder varias preguntas al mismo tiempo,
el diseño debe replantearse.

La simplicidad tiene prioridad sobre la cantidad de información.
